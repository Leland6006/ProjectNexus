# 第六轮：真实 OPC 试点、账号与企业关系

更新于 2026-10-19。根据用户最新要求，第六轮不是只找用户试用：必须先具备真实账号管理，以及企业之间添加好友和互动的能力。

当前第五轮仍为本机版。本文件为下一轮开发范围和验收标准，以下线上能力尚未实现，不能向真实用户承诺已经可用。

## 产品边界

- 个人账号是身份，企业是数据与协作主体。一个人可属于多个企业，必须先选定当前经营企业；成员权限由企业决定。
- 企业好友是双向同意的联系关系。成为好友不意味着可以看资金、企业记忆、内部讨论或全部合同。
- 资料共享发生在具体业务/合同上；AI 读取和所有操作仍遵守当前用户、企业及单项授权。
- Nexus 首页继续保持简洁对话入口。好友/联系人放在「业务与项目」二级导航；账号设置放在头像菜单，成员管理放在「公司档案与记忆」。

## 6A：身份与服务端基础（先做）

交付：真实注册、登录、邮箱验证、退出、会话失效、找回账号；账号资料与安全设置；新用户从空白企业资料开始，不混入演示数据。

采用成熟身份服务或成熟认证库，独立服务端 API 与 PostgreSQL，禁止自行把密码存进当前 JSON。MFA 和会话撤销纳入管理能力。具体托管商、域名、邮件发送服务、密钥与部署环境在实际接入时确定。

企业支持创建/加入、成员邀请、接受/撤回/失效、移除、角色调整、所有权转交；最后一个所有者不能被移除。角色至少覆盖所有者/管理员、经营、财务、法务、只读；外部顾问继续按项目独立授权。角色变更和账号停用即时影响已有会话。

个人身份、企业、企业成员关系分表。当前 User.orgId 的本机模型迁移为显式成员关系，actingOrg 从服务端认证会话及有效 membership 校验，不能相信客户端声明。

验收：两台设备登录同账号；不同账号不能互切；跨企业越权请求在服务端被拒绝；邀请与权限变更有审计；密钥不下发页面；公开试点构建移除模拟账号切换和重置演示入口。

## 6B：企业好友与联系人

交付：通过企业邀请码或准确的企业标识发起好友申请 → 对方授权成员接受/拒绝 → 双向企业好友 → 删除/屏蔽。展示企业名称与可验证的基本身份信息，避免同名企业自动关联。

本地 Counterparty 可由本企业管理员主动关联真实平台组织。关联须由双方确认，不按名称或邮箱静默合并，不改变既有历史合同的主体。

关系状态：pending / accepted / rejected / withdrawn / removed / blocked；记录申请方、接收方、操作者、理由、时间与修订号。无向企业对只能有一个有效关系，拒绝重复申请、自己加自己和并发双向重复。限制邀请频率，支持屏蔽举报，不暴露平台全部客户目录。

验收：另一家企业收得到申请；只有有权限的成员能代表企业处理；重复点击或双向同时申请不形成重复好友；屏蔽后不能继续申请或发送新消息；好友关系本身不授予合同或资金可见权限。

## 6C：企业互动与业务协作

交付：企业间会话、消息、未读与通知；从好友新建业务或邀请参与指定业务；共享指定合同，继续使用版本、评论、修改建议和内部审阅。

消息持久化到服务端，分配消息 ID、客户端幂等 ID 和顺序/游标；离线重连可补齐，不重复发送。第一阶段先做文字消息和明确分享的合同引用；附件在类型、大小、存储权限和扫描策略就绪后单独上线。

每条消息记录发送人及代表企业。企业会话与业务会话分开；用户能看清谁会收到。企业内部资金、发票资料、AI 对话和记忆默认不随消息或好友关系共享。转发或引用内部资料前必须预览并确认。

授权撤销和屏蔽停止新的互动/读取；既有合同历史、内部留存与协作退出分别制定清楚的规则，不能用删除好友静默销毁业务记录。AI 生成对外消息只先形成待确认草稿，不自动发送。

验收：两家企业、两个独立设备完成申请、接受、聊天、创建业务、共享合同、建议修改、内部审阅、双方确认版本；第三家企业无法枚举或读取；断网重连不丢消息；撤权后旧连接不能继续读写。

## 6D：真实试点与发布门槛

- 数据导入迁移有预览、备份与回滚；演示记录不得伪装成真实企业资料。
- 备份与恢复演练、关键写入审计、同步冲突处理、错误监控、费用上限与数据导出。
- 明示 AI 供应商、费用与数据发送范围；银行和税务仍未接通时，只保留用户记录，不声称核验。
- 测试账号和真实账号分环境，服务端强制权限，桌面应用签名/公证及更新方案完成后才开展外部试点。
- 先以少量 OPC 的「业务 → 合同 → 收付款核对 → 发票材料 → 下一步任务」闭环试用，记录任务成功率、纠错率、复用情况和持续使用意愿。

完成标准：真实用户可独立注册和建立企业，两家企业能在受控权限下建立关系并完成一笔协作，备份恢复和越权测试通过。不能以单机账号切换、静态好友列表或模拟消息代替。
