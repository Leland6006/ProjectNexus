# 第五轮与本地版整体优化

日期：2026-10-19。工作分支 `codex/round5-finance-polish`，保留第二至四轮未提交修改，未自动提交或推送。

## 资金与收支

schema v7 新增 CashPlan、CashEntry、InvoiceCase，旧数据通过增量迁移保留。

- 应收应付：用户核对总额、方向、预计日期和关联业务，支持日常公司事项、修订、取消和重新启用。
- 成本可关联为待付计划，同一成本不能重复建立有效计划。已发生核销的历史计划必须重新启用原计划，保留原核销，不能重录成本总额。关联期间成本原记录不可随意修改，避免金额不一致。
- 实际收支：必须选择本企业账户，填写实际日期、金额、说明与可区分的核对依据；可对计划部分核销。禁止未来实际收支、超额核销、方向/业务不一致、越权账户与重复记录。
- 写入有幂等操作编号；相同编号的不同内容拒绝。同账户/日期/金额/方向/核对依据的重复记录要求先核对。作废保留原记录、人员、时间与原因，恢复未结额。
- 账户余额是日终快照。只把快照日之后的有效记录加入或扣除；快照日当日及以前的记录可核销计划，但不再次改余额。更新快照不会重复加减历史记录。
- 不同日期的账户分别推算再汇总，公司只使用一次当前资金基数。未来计划仅计未核销部分；合同总额、节点金额和成本不自动再次叠加。未关联成本给出覆盖缺失提示。
- 预测显示按计划收付与未来收款全部延迟的两种结果。逾期计划假设今日发生，明确是假设，不是银行余额、会计收入或完整经营账。

## 发票材料与流程

- 关联业务，保存购买方信息、商品/服务、拟开票金额和待核对材料。
- 整理材料 → 人工核对 → 用户自行提交办理 → 用户记录结果，按顺序推进并留下历史；修改时可返回整理阶段。
- 号码及办理结果由用户提供，始终标注未连接税务系统验证，不自动开票、不判断税率与纳税义务，不自动产生收支。

## 整体优化

- 资金/发票二级导航正式启用；计划与发票待办进入首页及行动中心，直接到处理页面。
- 项目收付款页关联统一计划与实际记录；旧条款模拟遇已核销台账时停止，避免和统一公司台账重复计算。
- 财务 Agent 自动使用统一公司口径，保留源计划、实际记录和余额快照的引用；经营 Agent 收到明确标为条件预测、非单项目归因的结论。
- AI 可通过 finance_context 查询当前台账与预测；读取发票事项时隐藏购买方识别信息。聊天与分析期间台账变更会阻止保存旧结论。
- 成员页只显示当前企业成员，继续如实说明模拟账号与真实认证的边界。
- 统一上海业务日期；表单按钮默认不隐式提交；关联成本直接进入计划管理，取消的成本计划可重新启用。
- 合同编辑器延迟加载：首页主脚本由约 1.26 MB 降至 564 KB；编辑器单独约 703 KB，打开时加载。体积为构建未压缩 JS，不代表实际下载或启动耗时测量。
