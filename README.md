# Project Nexus

面向一人公司（OPC）与小团队创业者的「AI 联合创始人」工作空间：**以对话作为入口，以企业状态组织工作，以业务数据和可执行流程支撑回答。**
当前为本地桌面版（macOS，Electron），已完成第一轮产品框架改造。

> 所有企业、人员与合同内容均为**虚构演示数据**。账号切换与权限隔离仅用于本地演示，**不是**真实的身份认证。
> 本版本**没有接入任何 AI 模型**，Nexus 对话只保存消息并如实提示“尚未连接 AI”。

## 技术架构

Electron + electron-vite · React 18 + TypeScript · Tailwind CSS · Zustand · Tiptap · 本地 JSON 持久化。
详见 [ARCHITECTURE.md](ARCHITECTURE.md)。

## 安装与启动

需要 Node.js 22 或更高版本。

```bash
npm install
npm run dev
```

## 测试与构建

```bash
npm test            # 单元测试（权限、业务流程、会话、路由、版本比较、存储迁移、HTML 清理、编辑器规则）
npm run typecheck   # TypeScript 类型检查
npm run build       # 类型检查 + 生产构建
npm run dist        # 打包 macOS DMG
```

推送到 `main` 或发起 PR 时，GitHub Actions（`.github/workflows/ci.yml`）会自动执行 typecheck、测试与构建。

## 打包与签名

`npm run dist` 默认生成**未签名**的 DMG。未签名的应用在其他 Mac 上首次打开会被 Gatekeeper 提示，需要在“系统设置 → 隐私与安全性”中手动允许。

正式分发需要 Apple Developer 账号。在 `electron-builder.yml` 中启用 `identity` 与 `notarize`，并在打包前导出：

```bash
export APPLE_ID="you@example.com"
export APPLE_APP_SPECIFIC_PASSWORD="xxxx-xxxx-xxxx-xxxx"   # 在 appleid.apple.com 生成的应用专用密码
export APPLE_TEAM_ID="TEAMID"
```

然后把 `mac.identity` 改成你的 `Developer ID Application: …` 证书名称。CI 中建议把这些值放进仓库 Secrets，不要写进配置文件。

## 界面结构

从左到右：**一级模块导航 → 可折叠的二级侧栏 → 主内容区**。设置、账号与经营企业切换位于一级导航底部。

| 一级模块 | 二级导航 | 主内容 |
|---|---|---|
| Nexus | 新对话、搜索对话、最近聊天 | 对话首页（输入框、快捷入口、今日经营）与会话 |
| 行动与决策 | 经营概况、需要关注、待我决策、执行中（未启用）、已处理 | 企业状态、待决策方案及依据 |
| 业务与项目 | 新建业务、全部业务、全部合同、按交易对象分组、归档（未启用） | 业务工作区：概览与合同、协作与磋商、履约、收付款；三栏合同编辑器 |
| 资金与收支 | 资金概览、应收应付（未启用）、收支记录（未启用）、成本、发票（未启用） | 现金账户、成本台账与口径说明 |
| 公司档案与记忆 | 公司资料、已确认信息、待核实信息、资料库（未启用）、成员 | 可查看、确认、追溯的企业上下文 |

“当前经营企业”（切换会改变对话、资金与记忆范围）与“交易对象”（只改变当前查看的业务）在界面上分开显示。进入合同编辑器时二级侧栏自动收起。

## 当前已实现

- **Nexus 对话**：会话创建、继续、重命名、搜索，重启后保留；会话仅本人可见，按经营企业隔离；不会自动写入企业记忆。
- **今日经营 / 行动与决策**：只根据可见数据列出待决策方案、对方的修改建议和 14 天内到期或逾期的履约节点，每项注明来源与时间。
- **业务与项目**：创建/编辑/搜索/筛选、按交易对象分组、业务工作区、邀请对方与外部律师、项目消息与协商记录、履约节点、付款计划与成本。
- **合同**：模板起草、三栏编辑器、版本快照与差异比较与恢复、条款评论与回复、修改建议（接受/拒绝）、双方确认最终版。
- **AI 方案（协同分析）**：结构化付款条款变更 → 领域事件 → 法务/财务/经营三个视角（未接入模型时只有财务为真实计算）→ 一条待确认方案。
  采纳方案**不会**把它引用的推断或建议变成事实，事实只能逐条确认。
- 模拟账号切换与可见范围隔离、重启后数据保留。

## 已知限制

- 仅本地单机；账号切换不是真实认证；数据文件为明文 JSON（本地磁盘，未加密）。
- **未接入任何 AI 模型**。对话不会生成回答；协同分析中法务与经营视角显示“未接入模型，跳过”。
- 公司资料编辑、现金与成本录入、应收应付、实际收支、发票、任务执行、资料库均未实现，界面上以“尚未启用”说明，不显示虚假结果。
- 交易对象必须是已有的演示企业；“无需对方注册即可建立交易对象”尚未实现。
- 不支持 DOCX/PDF 导入导出与 OCR；无电子签章、无实时多人编辑；合同编辑器不是 Word 级别的修订追踪。
- 打包产物未签名、未公证。

## 演示流程

1. 启动后进入 **Nexus** 首页。输入一个问题并发送 → 生成会话，显示“尚未连接 AI”的状态说明和业务入口；重启后会话仍在。
2. 点「今日经营」中的条目，或进入 **行动与决策 → 需要关注**，跳到对应业务或合同。
3. **待我决策**：预置「智能设备采购项目」的一条方案（预付款 50%→10%，资金缺口 ¥342,000）。查看依据 → 可逐条「确认」→「采纳」或「忽略」。采纳后依据的状态不变。
4. **业务与项目**：新建业务 → 邀请对方 → 在「概览与合同」创建合同 → 编辑、保存新版本 → 版本历史比较差异。
5. 左下角头像切换为 **王志诚（远航精密 商务）** → 接受邀请 → 打开合同 → 提出修改建议、发表评论；确认看不到启明的对话和内部意见。
6. 切回陈思远 → 回复评论、处理建议；用法务 **林静怡** 授权外部律师 **周明哲** → 切换为周明哲添加律师意见。
7. 双方分别「确认最终版」→ 合同锁定 → 在业务的「履约」页创建节点，「收付款」页查看付款计划。
