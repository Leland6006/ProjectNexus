# Project Nexus

面向一人公司（OPC）与小团队创业者的「AI 联合创始人」工作空间：**以对话作为入口，以企业状态组织工作，以业务数据和可执行流程支撑回答。**
当前为本地桌面版（macOS，Electron），已完成第五轮资金事务与本地版整体优化。真实跨企业在线服务尚未接通。

> 所有企业、人员与合同内容均为**虚构演示数据**。账号切换与权限隔离仅用于本地演示，**不是**真实的身份认证。
> 本版本支持在「设置 → AI 连接」配置 DeepSeek API；默认不启用。未配置时只保存消息并提示“尚未连接 AI”。启用后，本次会话与相关授权企业数据会发送至 DeepSeek，并可能产生 API 费用。

## 技术架构

Electron + electron-vite · React 18 + TypeScript · Tailwind CSS · Zustand · Tiptap · 本地 JSON 持久化。
详见 [ARCHITECTURE.md](ARCHITECTURE.md)。

## 安装与启动

需要 Node.js 22 或更高版本。

```bash
npm install
npm run dev
```

## 测试与构建

```bash
npm test            # 单元测试（权限、业务流程、会话、路由、版本比较、存储迁移、HTML 清理、编辑器规则）
npm run typecheck   # TypeScript 类型检查
npm run build       # 类型检查 + 生产构建
npm run dist        # 打包 macOS DMG
```

推送到 `main` 或发起 PR 时，GitHub Actions（`.github/workflows/ci.yml`）会自动执行 typecheck、测试与构建。

## 打包与签名

`npm run dist` 默认生成**未签名**的 DMG。未签名的应用在其他 Mac 上首次打开会被 Gatekeeper 提示，需要在“系统设置 → 隐私与安全性”中手动允许。

正式分发需要 Apple Developer 账号。在 `electron-builder.yml` 中启用 `identity` 与 `notarize`，并在打包前导出：

```bash
export APPLE_ID="you@example.com"
export APPLE_APP_SPECIFIC_PASSWORD="xxxx-xxxx-xxxx-xxxx"   # 在 appleid.apple.com 生成的应用专用密码
export APPLE_TEAM_ID="TEAMID"
```

然后把 `mac.identity` 改成你的 `Developer ID Application: …` 证书名称。CI 中建议把这些值放进仓库 Secrets，不要写进配置文件。

## 界面结构

从左到右：**一级模块导航 → 可折叠的二级侧栏 → 主内容区**。设置、账号与经营企业切换位于一级导航底部。

| 一级模块 | 二级导航 | 主内容 |
|---|---|---|
| Nexus | 新对话、搜索对话、最近聊天 | 对话首页（输入框、快捷入口、今日经营）与会话 |
| 行动与决策 | 经营概况、需要关注、待我决策、执行中（未启用）、已处理 | 企业状态、待决策方案及依据 |
| 业务与项目 | 新建业务、全部业务、全部合同、按交易对象分组、归档（未启用） | 业务工作区：概览与合同、协作与磋商、履约、收付款；三栏合同编辑器 |
| 资金与收支 | 资金概览、应收应付、收支记录、成本、发票材料与办理记录 | 余额快照、计划/实际核销、公司条件预测与发票分步流程 |
| 公司档案与记忆 | 公司资料、已确认信息、待核实信息、资料库（未启用）、成员 | 可查看、确认、追溯的企业上下文 |

“当前经营企业”（切换会改变对话、资金与记忆范围）与“交易对象”（只改变当前查看的业务）在界面上分开显示。进入合同编辑器时二级侧栏自动收起。

## 当前已实现

- **Nexus 对话**：会话创建、继续、重命名、搜索，重启后保留；会话仅本人可见，按经营企业隔离；支持真实模型流式回复、停止生成、失败重试和本次数据依据，不会自动写入企业记忆。
- **今日经营 / 行动与决策**：只根据可见数据列出待决策方案、对方的修改建议和 14 天内到期或逾期的履约节点，每项注明来源与时间。
- **业务与项目**：无需对方注册的独立交易对象与联系方式、创建/编辑/搜索/筛选、按交易对象分组、业务工作区、邀请对方与外部律师、项目消息与协商记录、履约节点、付款计划与成本。
- **合同**：DOCX / 文字型 PDF 本机导入，字段候选与原文核对，人工确认后建立草稿；内部审阅与最终版确认约束；模板起草、三栏编辑器、版本快照与差异比较与恢复、条款评论与回复、修改建议（接受/拒绝）、双方确认最终版。
- **执行与协同**：持久化各专业分析节点与依据、暂停/恢复、失败重试；重启后中断运行转为待恢复。采纳方案创建去重的分步任务，可分配负责人、截止日期、记录每步结果。源数据变化需重新核对；任务完成只记录用户报告，不冒充外部办理事实。
- **AI 方案（协同分析）**：结构化付款条款变更 → 领域事件 → 法务/财务/经营三个视角（未接入模型时只有财务为真实计算）→ 一条待确认方案。
  采纳方案**不会**把它引用的推断或建议变成事实，事实只能逐条确认。
- **企业数据维护**：经营资料、现金账户余额、项目成本均支持编辑、修改预览与人工确认；项目收付款页可维护结构化付款安排及分期。
- **业务查询工具**：模型只能查询授权的公司背景、项目、合同正文、经营提醒及程序计算的现金流，并准备公司资料修改草稿；不能直接写入数据库或读取任意文件。
- **资金口径**：付款方、预计验收日、余额日期与成本必须齐备；已支付成本不重复扣除。多账户余额日期不同或历史付款未核对时暂停预测。单项目预测不是公司整体现金流。
- **连接设置**：API Key 经 Electron safeStorage / 系统密钥服务加密，单独存入本地 `ai-connection.enc`，不写业务 JSON、不回传给页面。页面输入框保存后清空；系统加密不可用时拒绝保存。断开连接会移除密钥。配置成功不代表远端认证已验证。
- 模拟账号切换与可见范围隔离、重启后数据保留。

## 已知限制

- 仅本地单机；账号切换不是真实认证；数据文件为明文 JSON（本地磁盘，未加密）。
- 默认未配置模型。配置后可调用真实 DeepSeek；本轮开发未使用真实 API Key 做远端付费调用验收，传输、工具循环和失败处理使用测试服务验证。
- 银行/税务等外部系统自动办理、资料库与专业法规检索尚未实现。模型不会自动办理或写入；聊天中可准备公司经营资料修改草稿，需本人点击确认；其他数据仍通过对应页面核对保存。
- Harness 隔离验证未通过：匹配版本的传递依赖发布缺失，未集成或启用；使用模型 API 与 Nexus 自己的流程运行层。详见 [验证记录](docs/HARNESS_EVALUATION.md)。
- 独立交易对象只有本企业本地记录，没有平台身份；线上邀请、关联真实账号和跨设备同步仍需认证与服务端。已有演示企业的邀请只在本机模拟。
- DOCX/PDF 仅导入文字，表格结构、排版、签章和附件可能丢失；原文件需自行保管。扫描 PDF 需先 OCR；尚无 Word/PDF 导出。无电子签章、无实时多人编辑；合同编辑器不是 Word 级别的修订追踪。
- 打包产物未签名、未公证。

## 演示流程

1. 启动后进入 **Nexus** 首页。输入一个问题并发送 → 生成会话，显示“尚未连接 AI”的状态说明和业务入口；重启后会话仍在。
2. 点「今日经营」中的条目，或进入 **行动与决策 → 需要关注**，跳到对应业务或合同。
3. **待我决策**：预置「智能设备采购项目」的一条方案（预付款 50%→10%，资金缺口 ¥438,000）。查看依据 → 可逐条「确认」→「采纳」或「忽略」。采纳后依据的状态不变。
4. **业务与项目**：新建业务 → 邀请对方 → 在「概览与合同」创建合同 → 编辑、保存新版本 → 版本历史比较差异。
5. 左下角头像切换为 **王志诚（远航精密 商务）** → 接受邀请 → 打开合同 → 提出修改建议、发表评论；确认看不到启明的对话和内部意见。
6. 切回陈思远 → 回复评论、处理建议；用法务 **林静怡** 授权外部律师 **周明哲** → 切换为周明哲添加律师意见。
7. 双方分别「确认最终版」→ 合同锁定 → 在业务的「履约」页创建节点，「收付款」页查看付款计划。

## 第二轮体验

1. 公司档案与记忆 → 公司资料 → 编辑经营信息 → 预览并确认。
2. 资金与收支 → 添加账户／更新余额；成本 → 添加或编辑成本。
3. 业务与项目 → 选择项目 → 收付款 → 编辑付款安排：核对付款方、预计验收日、账期与分期，并确认与合同正文一致。此操作保存结构化快照，不自动改写正文。
4. 设置 → AI 连接 → 输入 DeepSeek 模型名称和自己的 API Key，确认数据发送说明后启用。模型名可调整；默认 `deepseek-flash`，接口固定为官方 HTTPS 服务。
5. 回到 Nexus 询问项目或经营情况，展开回答下方的数据依据。更改成本后再次询问，会读取新快照。
6. 可以向 Nexus 明确提出修改公司行业或经营目标，核对回答下方的资料草稿并点击确认。生成草稿后若资料已变化，旧草稿不能覆盖。
7. 修改基础数据后，旧待决策方案失效，必须重新分析；采纳方案与事实确认仍是分开的。

开发验收可通过 `NEXUS_DEV_DATA_DIR=/tmp/nexus-dev-data npm run dev` 使用独立数据目录，不影响日常数据。该变量仅开发版生效。


## 第三、四轮体验

1. 行动与决策 → 待我决策 → 采纳方案，进入「执行与协同」；开始任务，逐步记录结果，可暂停后继续。
2. 业务页运行协同分析，或修改成本、付款安排、延期节点；在「执行与协同 → 协同记录」查看各专业过程与依据。未配置模型时专业解读明确跳过，财务仍按规则测算。
3. 业务与项目 → 新增交易对象，无需注册；新建业务时可直接选择。左侧按交易对象分组包含尚无业务的本地联系人。
4. 业务或全部合同 → 导入合同 → 选择 DOCX / 文字型 PDF → 核对识别原文、企业、金额与日期 → 确认建立新业务，或附加到已有业务。草稿可关闭后继续核对，确认重复提交不会重复创建。
5. 合同编辑器右侧「内部审阅」→ 选择本企业其他成员；切换到该演示账号处理并填写意见。发起审阅后，必须通过当前稿审阅才能确认最终版本；正文或版本变化需重新审阅。此流程属于本机模拟，不是线上电子签名。

完整范围、验证与剩余工作见 [第三、四轮交付记录](docs/ROUND3_4_DELIVERY.md)。


## 第五轮体验

1. 资金概览：录入账户日终余额与日期；之后只加减快照日之后的有效实际收支。
2. 应收应付：核对各笔计划；成本页可关联成本建立待付计划，不会叠加计算同一成本。
3. 收支记录：记录已核对的流水，关联计划进行部分核销。作废保留原因；历史错误涉及快照日及以前时，请重新核对余额。
4. 资金概览：查看全公司已录入计划的条件预测及收款延迟场景，未覆盖成本会提示；不是银行余额或完整会计核算。
5. 发票：整理资料 → 人工核对 → 用户自行办理 → 记录号码与结果。未接入税务系统，始终保留用户报告与未验证标识。
6. Nexus / 行动中心可以看到对应待办；财务 Agent 与 AI 业务查询可读取统一台账。合同编辑器按需加载，加快首页加载。
